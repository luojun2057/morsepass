# 分类分流规则

上传 Git 时，对每个变更文件按以下顺序判定去向。

## 判定顺序

- 项目级规则优先：ima-index.yaml 的 rules（glob 匹配，target: git | ima）；
- 命中即按规则走，未命中走默认规则；
- 仍拿不准 → 优先 Git，汇总表标注"待定"，用户一句话改判后记入项目 rules。
## 默认规则

||||
|---|---|---|
|源码/配置|*.vue *.ts *.js *.html *.css *.json *.yaml *.yml *.toml *.py *.sh|Git|
|项目文档|README.md、设计文档、卡片类 Markdown|Git（版本演进、需 diff/merge）|
|小素材|图标 SVG、<200KB 图片|Git|
|大参考文件|PDF、Office 文档（docx/xlsx/pptx）、音视频、>500KB 图片、文献、说明书|ima|
|大文件例外|大但需版本演进的设计源文件（如 .psd/.fig）|视情况：Git + Git LFS（P2）|


## 判据本质

Git 管演进（会改、要 diff/merge/回溯的），知识库管参考（大、重、纯查阅、喂 AI 检索的）。成品交付物：小文件可进 Git 留痕，大文件走 ima/云端网盘。

## ima 文本 vs 二进制

- ima 自动写入仅支持文本（Markdown 等纯文本）；
- 已验证（2026-10-01）：ima 保存接口不支持 .yaml 等扩展名（仅支持 md 等文本类型）——非 .md 文本文件同步到 ima 时需以 .md 包装（内容入代码块，标注真实扩展名），恢复时去包装；
- 已验证（2026-10-02 试点发现）：ima 保存同名文件默认另存不覆盖，自动追加 _YYMMDDHHMMSS 时间戳后缀（实证：SKILL.md 与 SKILL_261002002753.md 并存）——高频更新文件（镜像页/项目主页）必须显式 REPLACE 策略或改用带日期文件名；读取同名文件时取时间戳后缀最大的最新版（详见 SKILL.md「ima 同名另存与镜像刷新策略」）；
- 二进制（PDF/Office/图片/音视频）→ 待传清单路径：输出目标 ima 路径（X/分类/文件名）+ 命名规则 + 指引用户在 WorkBuddy 产物区手动上传；用户知会"已传"后索引闭环。
## 命名规则（ima 侧）

- 路径前缀：项目名/分类/，分类建议：docs（文档）、papers（文献）、assets（素材）、reports（报告）；
- 文件名保留原名，不重命名（索引靠原名对应）；
- 更新频繁的生成物（镜像页/目录页）REPLACE 不可用时改用带日期文件名（X-资料目录-YYYYMMDD.md）。

## 改判记忆

用户改判（如"这个 PDF 也进 Git"）→ 写入该项目 ima-index.yaml 的 rules，下次同类型自动按新规则走。
